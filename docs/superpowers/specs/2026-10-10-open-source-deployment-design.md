# 智审台容器化与开源交付设计

用户已确认：采用单容器部署，发布 `bennie-asi/cw-cr`，使用 MIT 许可证。

## 部署边界

一个镜像包含构建后的 React 页面、Nginx、Gunicorn 和持续评审 worker，由 Supervisor 托管。默认监听 8080，同源 `/api` 请求避免前后端 Cookie 域名差异。API 与 worker 位于同一容器，保留当前单机文件锁边界。默认 SQLite，可配置现有 PostgreSQL；不支持应用容器跨主机扩容。

命名卷 `/data` 保存 SQLite 数据库、Django 会话密钥、凭据加密密钥和运行锁。首次启动生成独立密钥并迁移数据库，后续启动保留密钥。已有密文而凭据密钥丢失时必须拒绝启动。管理员由部署者显式创建，无预置账号或密码。默认关闭 DEBUG，以非 root 用户运行；HTTP 快速启动只绑定主机回环地址，正式 HTTPS 部署启用 Secure Cookie。

## 变更

- Docker 多阶段构建、Compose 镜像部署与本地构建覆盖文件。
- 支持标准 SQLite 绝对路径 URL、文件形式 Django 密钥、Cookie 和 CSRF 部署配置。
- 测试不加载本地 `.env`，避免开发配置影响任务模式和认证回归。
- 中文 README、公开演示截图、详细部署/开发文档、MIT、贡献和安全报告入口。
- 排除本地数据库、秘密、缓存、浏览器配置、内部设计/验收档案；演示仓库与域名使用通用名称。
- CI 检查前后端测试、构建、迁移、隔离会话联调，以及真实容器启动、登录、重启持久化和 Compose。
- Docker workflow 支持 main、版本标签与手动触发，验证后发布 amd64/arm64 GHCR 镜像；PR 只验证。

## 验收与发布

本地 WSL Docker 实际构建并运行镜像，验证进程、同源登录/CSRF、SPA 刷新、数据/密钥持久化。运行完整前后端回归，不访问真实 GitLab、模型或企业微信。审核最终 Git 暂存内容，再创建公开仓库、推送 main、核对 Actions。只有镜像实际发布后才把 README 的预构建镜像说明视为可用；GHCR 包还需验证匿名拉取。

可选第三方评审 CLI 不进入默认轻量镜像；保留已有适配器并提供扩展镜像安装说明。正式 GitLab Webhook、模型推理及企微投递由部署者配置真实连接后验证。
